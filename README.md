# 💊 نظام إدارة الصيدليات الشامل

نظام متكامل واحترافي لإدارة الصيدليات باللغة العربية (RTL) يغطي دورة العمل الكاملة:
**المخزون · المبيعات · المشتريات · الأرباح · المصروفات · دليل الأدوية**.

---

## ✨ أهم المميزات

### 📚 دليل الأدوية (المرجع الدوائي)
- قاعدة مرجعية شاملة للأدوية (اسم تجاري، مادة فعالة، شكل صيدلاني، تركيز، شركة، بلد منشأ، باركود، كود ATC، ظروف التخزين، سعر شراء/بيع افتراضي، يصرف بوصفة؟).
- **لا يظهر في المخزون ولا يملك أي أرصدة** — مرجع فقط.
- يُستخدم لإدخال الأدوية بسرعة بطريقتين:
  1. زر **«إضافة للمخزون»** لتحويل الدواء إلى صنف مخزني (مع رصيد افتتاحي اختياري).
  2. مباشرة أثناء إنشاء **فاتورة شراء** — يتم إنشاء الصنف تلقائياً وربطه بالدليل.
- بحث وفلترة متقدمة + **استيراد جماعي** بصيغة CSV.

### 📦 المخزون
- إدارة الأصناف الفعلية مع الأسعار وحد إعادة الطلب وموقع الرف.
- **نظام الدفعات (Batches)**: رقم تشغيلة + تاريخ صلاحية + تكلفة لكل دفعة.
- الصرف بنظام **FEFO** (الأقرب انتهاءً يُصرف أولاً) وحساب تكلفة دقيقة لكل بند مبيع.
- تنبيهات: مخزون منخفض، نفد، قارب الانتهاء، منتهي الصلاحية.
- **تسويات مخزنية** (إدخال / إخراج / تالف / منتهي) + إتلاف جماعي للمنتهي.
- **سجل حركات كامل** لكل صنف (شراء، بيع، مرتجع، تسوية، إتلاف…).

### 🛒 المبيعات (نقطة بيع)
- شاشة بيع سريعة بالبحث بالاسم/المادة الفعالة/الباركود ودعم الماسح الضوئي.
- خصم على البند وعلى الفاتورة، ضريبة قابلة للضبط، طرق دفع (نقد/شبكة/تحويل/آجل).
- حساب الباقي للعميل وطباعة فاتورة حرارية احترافية.
- **مرتجعات جزئية أو كلية** مع إعادة الكميات إلى دفعاتها الأصلية.
- حساب **تكلفة البضاعة المباعة والربح لكل فاتورة** تلقائياً.

### 🚚 المشتريات
- فواتير توريد متعددة الأصناف مع رقم دفعة وتاريخ صلاحية وكميات بونص.
- ترحيل تلقائي للمخزون كدفعات جديدة وتحديث أسعار الشراء/البيع.
- متابعة المدفوع والمستحق للموردين وتسجيل الدفعات.
- إلغاء الفاتورة مع سحب الكميات (يُمنع إن تم بيع جزء منها).

### 💸 المصروفات
- تسجيل المصروفات التشغيلية بتصنيفات قابلة للإدارة (إيجار، رواتب، كهرباء…).
- رسم بياني لتوزيع المصروفات وربطها مباشرة بحساب صافي الربح.

### 📈 التقارير والأرباح
- **قائمة دخل كاملة**: المبيعات − المرتجعات − تكلفة البضاعة = مجمل الربح، ثم − المصروفات − خسائر التالف = **صافي الربح** وهامش الربحية.
- تقارير: المبيعات اليومية، حسب طريقة الدفع، أداء الموظفين، أفضل العملاء، الأصناف الأكثر ربحية، المشتريات حسب المورد، **تقييم المخزون** مع تصدير CSV.
- رسوم بيانية تفاعلية وطباعة التقارير.

### 🔐 الأمان والصلاحيات
- مصادقة JWT مع 4 أدوار: **مدير نظام / مدير صيدلية / صيدلي / كاشير**.
- **سجل نشاط** لكل عملية حساسة، ونسخ احتياطي بصيغة JSON.

## 🚀 التشغيل السريع

```bash
# 1) تثبيت الحزم
npm install

# 2) تجهيز قاعدة البيانات مع بيانات تجريبية واقعية
npm run seed          # أو: npm run reset  (يحذف القديم ويبني من جديد)

# 3) تشغيل الخادم والواجهة معاً
npm run dev
```

| الخدمة | العنوان |
|---|---|
| الواجهة | http://localhost:5173 |

## 🔐 حماية النسخ والتفعيل بمعرف الجهاز

النظام يدعم ربط كل نسخة بجهاز واحد، فلا تعمل إن نُسخت إلى جهاز آخر.

### كيف يعمل؟
- لكل جهاز **معرف ثابت** مشتق من مواصفاته (اسم الجهاز، المعالج، الذاكرة، النظام) بصيغة `XXXX-XXXX-XXXX-XXXX`.
- مفتاح التفعيل **موقّع رقمياً بخوارزمية Ed25519** ويحمل بداخله معرف الجهاز وتاريخ الانتهاء واسم العميل.
- التطبيق يحمل **المفتاح العام فقط**، والمفتاح الخاص يبقى عندك — فلا يمكن توليد مفاتيح من داخل النسخة المسلَّمة.
- ملف الترخيص يُحفظ في مجلد بيانات النظام، وإن نُسخ إلى جهاز آخر يرفضه النظام لاختلاف المعرف.

### التحديث باستبدال الملفات (بدون Git)
ملف `pharmacy-system.zip` في المستودع يحوي المشروع كاملاً ومحدّثاً. عند التحديث:

1. انسخ ملفات النسخة الجديدة فوق مجلد مشروعك.
2. مجلداك الخاصان **غير موجودين داخل الأرشيف ولن يُمسّا**: `server/data/` (قاعدة البيانات والنسخ الاحتياطية) و`tools/keys/` (مفاتيح الحماية).
3. نفّذ بعد الاستبدال:
```
npm install
npm run keygen sync
npm run app:build
```

> `keygen sync` يعيد كتابة مفتاحك العام داخل الكود (لأن الملف يأتي فارغاً في الأرشيف)،
> **وكل المفاتيح التي أصدرتها للعملاء تبقى صالحة** لأن زوج المفاتيح لم يتغيّر.

### التهيئة عندك (مرة واحدة)
```
npm run keygen init
```
يولّد زوج المفاتيح: الخاص في `tools/keys/private.pem` (مستثنى من Git — **لا يُسلَّم لأحد**)، والعام يُكتب تلقائياً داخل `server/src/lib/license-public-key.js`. بعدها أعد البناء: `npm run app:build`.

> ما دام المفتاح العام فارغاً، يعمل النظام **بدون تفعيل** — فلا شيء يتعطل قبل التهيئة.

### إصدار مفتاح لعميل
```
npm run keygen issue -- --machine A1B2-C3D4-E5F6-7788 --name "صيدلية النور"
npm run keygen issue -- --machine A1B2-C3D4-E5F6-7788 --days 365
npm run keygen issue -- --machine "*" --name "نسخة عرض"
```

| الأمر | الوظيفة |
|---|---|
| `npm run keygen machine` | عرض معرف الجهاز الحالي |
| `npm run keygen verify -- <KEY>` | التحقق من مفتاح |
| `npm run keygen list` | سجل المفاتيح الصادرة (`tools/keys/issued.json`) |

### عند العميل
يفتح البرنامج فتظهر **شاشة التفعيل** بمعرف جهازه وزر نسخ. يرسله لك، ترسل له المفتاح، يلصقه — ويُفتح النظام. وحتى التفعيل تبقى كل المسارات مغلقة (`HTTP 402`) عدا التفعيل وفحص الحالة.

> التفعيل مُلزم في تطبيق سطح المكتب المُغلَّف فقط. في وضع التطوير (`npm run dev`) يبقى معطلاً حتى لا يعيق العمل، ويمكن فرضه للاختبار بضبط `LICENSE_ENFORCE=1`.

## 💊 البيع بالتجزئة (وحدة أصغر من العبوة)

يمكن بيع **شريط من علبة** أو **قرص من شريط** أو **مل من زجاجة** دون أي إخلال بحسابات المخزون والأرباح.

### الإعداد لمرة واحدة لكل صنف
**المخزون ← تعديل الصنف ← البيع بالتجزئة**:

| الحقل | مثال |
|---|---|
| الوحدة الكبرى | علبة |
| الوحدة الصغرى | شريط |
| عدد الوحدات في العبوة | 10 |
| سعر بيع الوحدة الصغرى | 3.50 *(اتركه صفراً ليُحسب = سعر العبوة ÷ العدد)* |

> عادةً يكون سعر التجزئة أعلى من سعر العبوة مقسومًا — النظام يترك لك تحديده.

### في نقطة البيع
- فوق نتائج البحث مفتاح لتحديد مجال البحث: **الكل** أو **الاسم التجاري** أو **المادة الفعالة** (والباركود يعمل في كل الأوضاع).
- نتيجة البحث تعرض زرّين: **علبة · 30** و**شريط · 3.50** — اضغط أيهما شئت.
- كل بند في السلة فيه مفتاح تبديل **علبة ⇄ شريط**، والسعر يتغيّر تلقائيًا.
- نفس الصنف يمكن بيعه في الفاتورة نفسها بالوحدتين معًا كبندين منفصلين.
- الفاتورة المطبوعة تُظهر «3 شريط» لا «0.3».

### كيف تُحسب الأرقام؟
بيع 3 أشرطة من علبة بـ10 أشرطة (تكلفة العلبة 20، سعر الشريط 3.5):

| القيمة | النتيجة |
|---|---|
| إجمالي البند | 3 × 3.5 = **10.50** |
| المخصوم من المخزون | 0.3 علبة |
| تكلفة المبيعات (COGS) | 0.3 × 20 = **6.00** |
| الربح | **4.50** |

- الرصيد يُعرض بصيغة مفهومة: **«8 علبة و4 شريط»** بدل 8.4.
- **المرتجعات** تتم بنفس وحدة البيع: ترجع «شريطين» فيعود 0.2 علبة للمخزون.
- صرف **FEFO** وتواريخ الصلاحية والدفعات تعمل كما هي مع الكميات الكسرية.
- أعمدة التجزئة الأربعة مضافة إلى **تصدير واستيراد Excel** للمخزون.

> النظام يمنع: البيع بالتجزئة لصنف غير مفعّل، أو كمية كسرية من الوحدة الصغرى (نصف شريط)،
> أو إرجاع أكثر من المتبقي — برسائل عربية واضحة.

## 🌐 التشغيل على شبكة الصيدلية (عدة أجهزة)

يدعم التطبيق ثلاثة أوضاع تختارها من **الشبكة ← إعدادات الشبكة…** داخل البرنامج
(أو `Ctrl+Shift+N`):

| الوضع | الوصف | متى تستخدمه |
|---|---|---|
| **جهاز واحد** *(افتراضي)* | خادم داخلي على `127.0.0.1` بمنفذ عشوائي، لا يستقبل أي اتصال من الشبكة | صيدلية بجهاز واحد — الأكثر أماناً |
| **خادم الشبكة** | قاعدة البيانات على هذا الجهاز، ويستقبل اتصالات الأجهزة الأخرى على منفذ ثابت (`4100` افتراضياً) | الجهاز الرئيسي في الصيدلية |
| **متصل بالشبكة** | لا يحتفظ بأي بيانات محلية، بل يعمل على بيانات الجهاز الرئيسي لحظياً | أجهزة الكاشير الإضافية |

### الإعداد في ٣ خطوات
1. على **الجهاز الرئيسي**: افتح إعدادات الشبكة ← اختر «خادم الشبكة» ← احفظ (يعيد التطبيق تشغيل نفسه).
   عند أول تشغيل سيسأل ويندوز عن جدار الحماية → اختر **السماح** للشبكات الخاصة.
2. انسخ الرابط الظاهر، مثل `http://192.168.1.10:4100`.
3. على **بقية الأجهزة**، اختر واحدة من طريقتين:
   - **بدون تثبيت**: افتح الرابط في متصفح Chrome/Edge مباشرة.
   - **بالتطبيق**: ثبّت نفس ملف الـ EXE ← إعدادات الشبكة ← «متصل بالشبكة» ← اكتب الرابط ← **اختبار الاتصال** ← احفظ.

### تفاصيل تهمّك
- كل الأجهزة تعمل على **نفس قاعدة البيانات لحظياً** — بيع من الكاشير ينقص المخزون فوراً عند الجميع.
  (كل الكتابات تمرّ عبر الخادم الرئيسي وSQLite بوضع WAL، فلا تعارض ولا فقدان بيانات.)
- النسخ الاحتياطي يؤخذ من **الجهاز الرئيسي فقط**، لأنه صاحب البيانات.
- يُفضّل حجز **IP ثابت** للجهاز الرئيسي من إعدادات الراوتر حتى لا يتغيّر الرابط.
- إن توقّف الجهاز الرئيسي، تعرض الأجهزة الفرعية رسالة واضحة وتفتح نافذة إعدادات الشبكة تلقائياً.
- **الأمان**: النظام يقبل 8 محاولات دخول فاشلة فقط خلال 10 دقائق ثم يوقف المحاولات 5 دقائق لنفس المستخدم والجهاز.
  استخدم النظام داخل شبكة الصيدلية الخاصة فقط، ولا تفتح المنفذ على الإنترنت.

## 📊 استيراد وتصدير Excel

كل من **المخزون** و**دليل الأدوية** يدعمان التصدير والاستيراد بصيغة `.xlsx` (وكذلك `.csv`).

| الزر | ماذا يفعل |
|---|---|
| **تصدير Excel** | ينزّل البيانات الظاهرة (مع احترام الفلاتر: البحث، التصنيف، النافد، المنخفض) في ملف منسّق عربي RTL مع عناوين ملوّنة وتصفية تلقائية |
| **تنزيل القالب** | ملف فارغ بالعناوين الصحيحة + ورقة **تعليمات** تشرح كل عمود وإلزاميته |
| **فحص الملف** | تشغيل تجريبي (Dry run) يعرض كم سجلاً سيُضاف ويُحدَّث ويُتجاهل، وجدول الأخطاء بأرقام الصفوف — **دون حفظ أي شيء** |
| **تنفيذ الاستيراد** | ينفّذ العملية داخل معاملة واحدة (إما أن تنجح كلها أو تُلغى) |

**ترتيب الأعمدة**: تفاصيل الدواء أولاً (اسم الصنف، الاسم العلمي، الشكل، التركيز، الوحدة، التصنيف، الشركة المصنعة)، تليها مباشرة أعمدة الإدخال السريع (الباركود، سعر الشراء، سعر البيع، الكمية، تاريخ الصلاحية، رقم الدفعة)، ثم إعدادات البيع بالتجزئة.

**تفعيل البيع بالتجزئة تلقائياً**: بمجرد كتابة اسم في عمود «الوحدة الصغرى» مع «عدد الوحدات بالعبوة» يُفعّل النظام البيع بالتجزئة للصنف تلقائياً. وإن كتبت الوحدة بدون العدد يظهر تنبيه في نتيجة الاستيراد.

**كيف يطابق النظام السجلات؟** بالمعرف (id) أولاً، ثم الباركود، ثم الاسم. يمكنك اختيار
«تحديث الموجود» أو «إضافة الجديد فقط».

**عمود «الكمية»** يضبط رصيد الصنف — للأصناف الجديدة والموجودة على حد سواء:

| ما تكتبه في الخلية | ما يفعله النظام |
|---|---|
| تتركها فارغة | لا يمسّ الرصيد إطلاقاً |
| رقم أكبر من الرصيد الحالي | يضيف الفرق كدفعة جديدة (برقم الدفعة وتاريخ الصلاحية المكتوبين) |
| رقم أقل من الرصيد الحالي | يخصم الفرق من أقرب الدفعات انتهاءً |
| صفر | يصفّر رصيد الصنف بالكامل |

كل تغيير في الرصيد يُسجَّل في **حركات المخزون** باسمك مع ذكر الرصيد قبل وبعد، ويظهر في
الفحص التجريبي قبل التنفيذ: كم صنفاً سيتغير رصيده وكم وحدة ستُضاف أو تُخصم.

الأعمدة المحسوبة (الكمية المتوفرة، قيمة التكلفة، أقرب صلاحية) تُصدَّر للاطلاع فقط ويتجاهلها النظام عند الاستيراد.

### تعديل تواريخ الصلاحية والأسعار بعد الإدخال
تواريخ الصلاحية والأسعار تخص **الدفعة** لا الصنف، ولذلك تُعدَّل من مكانين:

- **داخل التطبيق**: المخزون ← تبويب «الصلاحيات» أو تفاصيل الصنف ← زر ✏️ بجانب الدفعة ← تعديل رقم الدفعة وتاريخ الصلاحية وسعر التكلفة وسعر البيع.
- **من Excel**: المخزون ← «الصلاحيات» ← **تصدير Excel** ← عدّل الأعمدة ← **استيراد Excel**. عمود «معرف الدفعة» هو مفتاح التحديث ولا يُغيَّر.

> الكمية لا تُعدَّل من هذين الطريقين عمداً — تُعدَّل عبر «تسوية مخزنية» حتى تبقى حركة المخزون موثّقة.

## 📝 مسودة فاتورة الشراء (حماية من انقطاع التيار)

أثناء إدخال فاتورة شراء يحفظ النظام ما تكتبه **مسودة تلقائية** على الخادم كل ثانية تقريباً،
ويظهر وقت آخر حفظ في عنوان النافذة.

لو انقطع التيار أو أُغلق البرنامج فجأة، تجد عند فتح صفحة المشتريات شريطاً يعرض عدد الأصناف
وقيمتها ووقت آخر حفظ، مع زرَّي **استعادة ومتابعة الإدخال** أو **تجاهل وحذف**.
وعند حفظ الفاتورة نهائياً تُحذف المسودة تلقائياً.

> المسودة لا تمسّ المخزون ولا الحسابات إطلاقاً — هي نص محفوظ فقط حتى تُرحَّل الفاتورة فعلياً.
> ولكل مستخدم مسودته الخاصة.

## 💾 النسخ الاحتياطي والاستعادة ومسح البيانات

من **الإعدادات ← النسخ والصيانة**:

### نسخ احتياطي
- **تنزيل نسخة**: ملف JSON واحد يضم كل شيء — الإعدادات، المستخدمين وكلمات مرورهم المشفّرة،
  دليل الأدوية، الأصناف والدفعات، المبيعات والمشتريات والمصروفات وحركات المخزون.
- **حفظ نسخة على الجهاز**: تُخزَّن داخل `<مجلد البيانات>/backups` مع قائمة بالنسخ (تنزيل / حذف)،
  ويحتفظ النظام تلقائياً بآخر 20 نسخة.

### استعادة نسخة
1. اختر ملفاً من جهازك أو نسخة محفوظة.
2. يعرض النظام **ملخص الفحص**: عدد السجلات في كل جدول، عدد المستخدمين، والتحذيرات.
3. أدخل كلمة مرورك للتأكيد.
4. يُنشئ النظام **نسخة أمان تلقائية** ثم يستبدل كل البيانات، ويتحقق من ترابطها (`foreign_key_check`).

> إن كانت النسخة بلا كلمات مرور أو بلا مدير نظام نشط، يُبقي النظام على المستخدمين الحاليين
> حتى لا تفقد الدخول أبداً.

### مسح بيانات النظام
ثلاثة نطاقات واضحة:

| النطاق | يُحذف | يبقى |
|---|---|---|
| **الحركات فقط** | المبيعات، المشتريات، المصروفات، الدفعات، حركات المخزون | الأصناف والدليل والموردون والعملاء |
| **الحركات وأصناف المخزون** | ما سبق + أصناف المخزون | دليل الأدوية والموردون والعملاء |
| **كل بيانات العمل** | ما سبق + الموردون والعملاء | المستخدمون والإعدادات |

مع خيارين إضافيين: حذف **دليل الأدوية**، وحذف **سجل النشاط**.
التنفيذ يتطلب كتابة كلمة «مسح» + كلمة مرور مدير النظام، ويسبقه إنشاء نسخة أمان تلقائية.
المستخدمون والإعدادات لا تُمس في جميع الحالات.

## 🖥️ تطبيق سطح المكتب (ملف EXE لويندوز)

النظام جاهز للتحويل إلى برنامج ويندوز مستقل عبر **Electron** — بنقرة واحدة، بدون متصفح
وبدون أن يحتاج جهاز الصيدلية إلى تثبيت Node.js.

```powershell
npm install
npm run app:start
npm run app:build
```

| الأمر | ماذا يفعل |
|---|---|
| `npm run app:start` | تجربة التطبيق كنافذة سطح مكتب |
| `npm run app:build` | إنتاج المثبّت + النسخة المحمولة داخل مجلد `release/` |

**لا حاجة لأي مترجم C++ ولا لأي وحدة أصلية.** إصدارات Electron 40 وما بعدها تحزم
Node.js 24 الذي يتضمن محرك `node:sqlite` جاهزاً، ويلتقطه النظام تلقائياً.

> ⚠️ نفّذ كل أمر وحده. لا تنسخ أي تعليق بعده على نفس السطر — موجّه الأوامر `cmd.exe`
> لا يفهم `#` كتعليق فيمرّره إلى البرنامج وتظهر رسالة مثل `Unknown target: #`.

| المخرج | الوصف |
|---|---|
| `release/PharmacySystem-1.0.0-x64.exe` | مثبّت كامل مع اختصار سطح المكتب وقائمة ابدأ |
| `release/PharmacySystem-1.0.0-portable.exe` | نسخة محمولة تعمل من فلاشة بدون تثبيت |

**مميزات نسخة سطح المكتب:** شاشة إقلاع، قائمة عربية كاملة (طباعة، حفظ PDF، نسخ احتياطي
لقاعدة البيانات، فتح مجلد البيانات)، حفظ أبعاد النافذة، منع تشغيل أكثر من نسخة،
واختيار تلقائي لمنفذ محلي حر. البيانات تُحفظ في
`%APPDATA%\Pharmacy System\data` فلا تتأثر بالتحديث أو إعادة التثبيت،
وعند أول تشغيل يُعبّأ **دليل الأدوية (68 دواء)** تلقائياً مع بقاء المخزون فارغاً للبدء الحقيقي.

📖 التفاصيل الكاملة وحل المشكلات: [`electron/README.md`](electron/README.md)

## 📋 ملاحظات تشغيلية

- الأسعار والعملة قابلة للتغيير من **الإعدادات** (ر.س / ر.ي / ج.م …) وتنعكس على كل الشاشات والفواتير.
- نسبة الضريبة وحد المخزون المنخفض وأيام تنبيه الصلاحية كلها قابلة للضبط.
- المشتريات **لا تُحتسب مصروفاً**، بل تتحول إلى مخزون وتظهر تكلفتها عند البيع (محاسبياً صحيح).
- يعتمد الخادم على SQLite عبر `node:sqlite` المدمج في Node.js (راية `--experimental-sqlite` على Node 22، وجاهز بلا راية على Node 24 وداخل Electron 40+)، ويستخدم `better-sqlite3` تلقائياً إن كان مثبتاً.
- عند أول تشغيل على قاعدة بيانات جديدة يُنشأ حساب `admin/admin123` ويُعبّأ دليل الأدوية تلقائياً.
