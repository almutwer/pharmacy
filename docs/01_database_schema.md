# 01 - SQLite Database Schema

تم اعتماد هذا التصميم كأول مرحلة قبل كتابة الكود. الملف التنفيذي الكامل موجود في:

- `db/schema.sql`
- بيانات تجريبية: `db/sample_data.sql`

## المبدأ المعماري الأساسي

لا يوجد خلط بين دليل الأدوية العام والمخزون الفعلي:

| الطبقة | الجدول | الهدف | هل يتغير بالمبيعات؟ |
|---|---|---|---|
| A | `medicines_catalog` | دليل عام للأدوية المسجلة في الدولة | لا |
| B | `pharmacy_inventory` | الموجود فعلياً على رفوف هذه الصيدلية | نعم، الكمية تنقص فقط من هنا |
| C | `sales`, `sale_items` | الفواتير والحركات اليومية | يسجل عمليات البيع |

## أهم الجداول

### `medicines_catalog`

جدول مرجعي للبحث فقط. لا يحتوي على كمية أو دفعة أو تاريخ انتهاء.

أهم القيود:

- `barcode` فريد.
- `trade_name` مطلوب.
- السعر الرسمي لا يمكن أن يكون سالباً.
- محمي بــ Trigger يمنع الكتابة إلا في وضع استيراد الدليل.

### `pharmacy_inventory`

يمثل الدفعات الموجودة فعلياً. كل سجل يرتبط بدواء في الدليل عبر `catalog_id`.

أهم القيود:

- `quantity >= 0`.
- `purchase_price >= 0`.
- `selling_price >= 0`.
- منع إضافة دواء بتاريخ انتهاء سابق.
- نفس الدواء يمكن أن يظهر في أكثر من دفعة.

### `sales` و `sale_items`

كل فاتورة لها رقم مسلسل بصيغة:

```text
INV-YYYY-NNNNNN
```

ويتم توليده داخل Transaction واحدة حتى لا تظهر فجوات عند فشل العملية.

### `stock_movements`

يسجل كل حركة كمية:

- استلام مخزون
- بيع
- تعديل يدوي
- إرجاع
- Quick Add

### `audit_log`

يسجل العمليات المهمة:

- إضافة مخزون
- تعديل أسعار أو كميات
- إنشاء فاتورة
- إضافة صنف لفاتورة
- التحذير عند البيع بأقل من سعر الشراء

## Triggers الحرجة

- منع البيع عند عدم توفر الكمية.
- منع بيع الدواء منتهي الصلاحية.
- خصم المخزون تلقائياً عند إدخال `sale_items`.
- منع الحذف النهائي من الجداول التشغيلية.
- منع تعديل رقم الفاتورة.
- حماية دليل الأدوية من التعديل خارج شاشة الاستيراد.
